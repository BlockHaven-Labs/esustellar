# Grafana dashboards — provisioned as code, edited as JSON

`editable: false` is set on the dashboard provider in
`dashboard-provisioning.yaml`. That is deliberate: these dashboards are
**generated from the JSON in this directory**, not edited in the Grafana UI.

## Why UI edits are the wrong place to work

Grafana's file-based provisioning re-reads the provider path on every restart
and **overwrites** whatever is in the database for dashboards whose UID matches
a file in the provider path. Concretely:

- Make a change in the Grafana UI (edit a panel, add one, move one) → Grafana
  persists it to its local storage only.
- The next pod restart, rollout, `kubectl rollout restart`, or node reschedule
  wipes the UI change and restores the committed JSON. Nothing warns you; the
  edit simply disappears.
- `grafana-storage` is a `ReadWriteOnce` PVC mounted at `/var/lib/grafana`, so
  the dashboards are also not reproducible across environments — each cluster
  drifts independently.

The same is true of the datasources (`datasources/datasources.yaml`) and the
provisioning file itself: all three are mounted as ConfigMaps generated by
`../kustomization.yaml`, so the cluster copy is regenerated on every apply.

## The required workflow

1. **Make dashboard changes in the JSON files in this directory.** Use the UI
   only as a scratchpad for exploring queries or panel layouts you are not yet
   sure about.
2. **If you did make a change in the UI, export it before you leave:**
   Dashboards → your dashboard → *Share* → *Export* → *Export for sharing
   externally* → save as JSON.
3. **Reconcile the exported JSON with the committed file** before committing.
   The exported file contains runtime noise (dashboard `version`, `iteration`,
   panel `id`s, `time` windows) that produces large, unreviewable diffs. Strip
   it down to what you actually changed; keep `uid`, `title`, `panels[]`,
   `templating` and `time` as-is.
4. **Validate locally** (the same checks CI runs in
   `.github/workflows/monitoring-dashboard-validation.yml`):
   ```bash
   # structural: must be parseable JSON with a uid and at least one panel
   jq -e '.uid and (.panels | length > 0)' infra/monitoring/grafana/dashboards/*.json

   # metric names referenced must exist in the alert rules / exporter
   # (this is the `monitoring-dashboard-validation.yml` job)
   ```
5. **Commit the JSON.** The apply path is:
   `git push` → overlay apply → `kustomize build` regenerates the
   `grafana-dashboard-files` ConfigMap → Grafana picks it up on restart.
6. **Restart Grafana to pick up the change:**
   ```bash
   kubectl -n esustellar-monitoring rollout restart deploy/grafana
   kubectl -n esustellar-monitoring rollout status  deploy/grafana
   ```

## Files in this directory

| File | Contents |
| ---- | -------- |
| `web-app-golden-signals.json` | RED method dashboard for the web app: request rate, error ratio, latency percentiles. |
| `on-chain-events.json` | Contract/event throughput and deployer-balance metrics sourced from the balance exporter. |
| `dashboard-provisioning.yaml` | The Grafana provisioning file itself (ConfigMap `grafana-dashboards-provisioning`). Its provider `path` must match the volumeMount in `../grafana-deployment.yaml` (`/var/lib/grafana/dashboards`). |

## Adding a dashboard

Add `<new-dashboard>.json` to this directory **and** to the `files:` list of the
`grafana-dashboard-files` generator in `../kustomization.yaml`. The ConfigMap is
generated from an explicit file list, so a JSON file dropped in here without
that edit is silently never deployed.

Give every dashboard a stable, unique `uid` (e.g. `esustellar-web-golden-signals`).
The `uid` — not the title — is what Grafana matches on when deciding whether a
provisioned file replaces an existing dashboard, so changing it orphans the old
dashboard rather than updating it.

## Local development

Grafana and Prometheus run locally via `docker compose` (see `infra/README.md`).
The local compose stack mounts `dashboards/*.json` directly from this directory,
so a JSON edit is visible after a Grafana restart there too.
